# Google Play Console 提出チェックリスト（FairClass スマホ・タブレット版）

`mobile/`（Expo SDK 57・Android）を Google Play に初めて出すまでの全項目を、Play Console で実際に触る順に並べた。
既存アプリ UnitCalc（`ohru131/si-unit-calculator` の `docs/android-submission-checklist.md`）の手順を下敷きにしているが、
**FairClass は広告・AdMob・アカウントが無く、扱うデータ（名簿）も違う**ので、答えは全部 FairClass のコードから取り直してある。

関連資料（このフォルダ）:

| [`reviewer-instructions.md`](reviewer-instructions.md) | App access の回答・審査員への説明（英語）・Pro を課金せずに試す方法 |
| [`pricing.md`](pricing.md) / [`pricing.csv`](pricing.csv) | Pro の国別価格と根拠、`scripts/push-play-pricing.mjs` での反映 |

## 3. ストアの設定（「拡大」→「ストアの設定」）

- [ ] **アプリのカテゴリ**: **教育（Education）**を推奨
  - 理由: 利用者（教員）が教員向けの道具を探しに行く棚で、Google Classroom・ClassDojo・座席表・班分けのアプリもここにある。
    「仕事効率化（Productivity）」はメモ・オフィス・タスク管理が中心で、「クラス分け」「班分け」と並ぶ相手がいない。
  - カテゴリを教育にしても、**ファミリー ポリシーがかかるかはカテゴリではなくターゲット層で決まる**（13 歳以上なら対象外）。
    ただし教育カテゴリは子ども向けアプリが多いので、掲載の絵と文が子ども向けに見えないようにする（`content-rating.md` 2節）。
  - 迷ったら: 教育で出し、検索流入（「クラス分け」「class placement」）が伸びなければ仕事効率化で比べる（カテゴリはいつでも変えられる）。
- [ ] **タグ**: 「教育」系のタグから教員向け・学校の運営に近いものを最大5つ【要確認：Play Console の候補一覧で選ぶ】

- [ ] **外部マーケティング**: 既定（Google のマーケティングに使ってよい）でよい

## 5. アプリ内アイテムと課金（「収益化」→「商品」→「一回限りの商品」）

- [ ] お支払いプロファイルを紐付ける（未設定だと商品を作れない）
- [ ] **一回限りの商品**を作成: 商品 ID **`fairclass_pro`**（**作ったら変えられない・削除しても同じ ID は再利用できない**）
  - 名前: `FairClass Pro`（言語ごとの名前・説明も入れる。例: ja「FairClass Pro（買い切り）」「Excel への書き出しと印刷・PDF」）
  - 購入オプション: 「購入（Buy）」1つ。**基準価格 US$5.99** を入れて保存・有効化
  - 国別価格: [`pricing.csv`](pricing.csv) を `node scripts/push-play-pricing.mjs --commit` で反映（[`pricing.md`](pricing.md)）
  - **定期購入（サブスクリプション）は作らない。**
  - Google Play の一回限りの商品は、**消費（consume）されると再び買える＝買い切りではなくなる**。消費するかどうかを決めるのは
    アプリのコードではなく **RevenueCat**: SDK は購入を RevenueCat に送り、返ってきた商品ごとの `should_consume` に従って consume する
    （`react-native-purchases` が内部で使う purchases-android の `PostReceiptHelper`。RevenueCat の SDK のメッセージも
    「ダッシュボードで一回限りの商品を消費型か非消費型か正しく設定せよ」と案内している）。**RevenueCat は Google Play の
    一回限りの商品を既定で消費型として扱う**ので、下の「非消費型の設定」をしないと Pro が consume され、復元できない・再購入できてしまう。
- [ ] **RevenueCat**（`mobile/README.md` の「RevenueCat の設定」）
  - [ ] RevenueCat のプロジェクトに Android アプリ（パッケージ名＝上の App ID）を作る
  - [ ] **Play のサービス アカウントの認証情報**を RevenueCat に登録（購入の検証に要る。権限が反映されるまで最大 36 時間かかることがある【要確認】）
  - [ ] （推奨）リアルタイム デベロッパー通知（Pub/Sub）を RevenueCat の案内どおりに設定（返金の反映が早くなる）
  - [ ] 商品 `fairclass_pro` を取り込み、**Entitlement `pro`** に紐付ける（紐付け忘れると支払っても Pro にならない）
  - [ ] **RevenueCat のダッシュボードで商品 `fairclass_pro` の種類を「Non-consumable（非消費型）」に設定する（必須）**。
    **Lifetime パッケージに入れるだけでは非消費型にならない**（パッケージの種類は offering の中の並べ方で、consume するかどうかとは別の設定）
  - [ ] Offering（current）に **Lifetime パッケージ**として入れる
  - [ ] 内部テストでライセンステスターとして購入 → アプリを入れ直して「購入を復元」で Pro が戻ること、もう一度「購入」しようとすると「購入済み」になることを確かめる（consume されていればどちらも失敗する）
  - [ ] Android の公開 SDK キー（`goog_…`）を EAS の環境変数 `EXPO_PUBLIC_REVENUECAT_ANDROID_API_KEY` に登録してからビルド
- [ ] **ライセンス テスト**: 「設定」→「ライセンス テスト」に自分とテスターの Google アカウントを追加（課金されずに購入を試せる）

## 9. テストとリリースのトラック

| トラック | 使い方 |
|---|---|
| 内部テスト（最大100人・審査が速い） | 最初のビルドの動作確認。自分の端末・タブレット・Chromebook で購入（ライセンステスター）・復元・印刷・Excel 共有を確認 |

### クローズドテストの計画（個人アカウントの場合）【要確認：規約の人数・日数】

- [ ] **テスター 12 人以上が、オプトインしたまま 14 日間連続**で参加している必要がある（途中で抜けると数え直し）。余裕を見て **15〜20 人**集める。
- [ ] 集め方: 同僚・知人の教員、教員コミュニティ。**Google グループ**を作ってテスターのリストに登録すると管理が楽（メールのリストでも可）。
  南米・韓国の知人がいればその言語でも見てもらう（翻訳はネイティブの確認を受けていない。`docs/i18n-glossary.md` 第4節）。
- [ ] 案内に入れること: オプトインの URL、Play ストアからのインストール方法、**14日間アンインストールしないで**、毎日でなくてよいので数回開いて
  サンプルで編成→結果→手直しを試してほしい、フィードバックの送り先（Google フォーム等）。Pro はライセンステスターに登録して課金なしで試してもらう。
- [ ] 期間中に1回以上ビルドを更新し、フィードバックへの対応を記録する（本番申請の質問票で「テストで何を学び、何を直したか」を聞かれる）。
- [ ] 14日経過後、ダッシュボードの「製品版へのアクセスを申請」で質問票に答える（テストの募集方法・得られたフィードバック・本番への準備）。審査は通常数日【要確認】。
- 時期: 日本・韓国の編成の山は 2〜3月、南米は 12〜2月。**本番公開を 1月中に**間に合わせるなら、クローズドテストは **12月上旬に開始**する。

## 10. 事前リリース レポート（Pre-launch report）

- クローズド・内部テストに上げると自動で実機テスト（Robo）が回る。ログイン情報は要らない（`reviewer-instructions.md`）。

## オーナーが手で行う残りの作業（まとめ）

1. ~~App ID を確定~~（`com.ohru131.mosaic` で確定済み。0 節）。
2. 公開する連絡先メール・デベロッパー名を決める。
3. お支払いプロファイル・税務情報・本人確認。
4. EAS プロジェクトの作成、RevenueCat のプロジェクト・Android アプリ・`pro` entitlement・**商品を非消費型に設定**・Lifetime の offering、SDK キーを EAS へ。

8. 実機で撮ったスクリーンショットと見比べ、Web 書き出しの素材（`submission-assets/`）と違いが大きければ差し替える。
